## 背景

当前工程已经支持浏览器本地处理和无模型的 `cv_native` 后端处理。它们都能输出目标尺寸的 RGBA 格子图，之后由前端完成拼豆色板匹配、统计、渲染和导出。对于颜色、纹理接近或主体形状复杂的图片，纯 CV 方法存在主体识别上限。

本需求探索一个低成本的轻量终端 AI 算法，在保留前端业务职责和失败回退能力的前提下，用开放集检测和轻量分割改善主体/背景分区，再交给现有像素化和前端拼豆流程。

## 目标

新增一个独立的后端算法模式 `tiny_model@1.0.0`，处理流水线为：

```text
图像输入 → Prompt 指定主体 → 开放集检测 → 轻量分割
→ 透明边裁切与主体等比放大 → 主体边缘增强
→ 主体内部/轮廓保护区可控像素化 → 固定分辨率 RGBA 输出
```

用户可在 Pattern settings 中选择该模式，并在该模式下输入主体 Prompt。后端成功时返回统一算法输出；后端不可用或结果无效时，前端自动使用现有浏览器处理逻辑并显示既有的 5 秒可关闭回退通知。

## 用户可感知行为

1. Pattern settings 始终显示轻量 AI 模式选项。后端能力接口确认算法和模型可用时允许选择；不可用时禁用并明确显示原因。运行期间发生故障时执行浏览器回退。
2. 用户上传 JPG/PNG 原图并点击 Generate 后才开始处理。生成期间相关输入控件锁定，完成后恢复 Download。
3. Prompt 用于指定要保留的主体，允许描述多个主体或多个实例。多个目标短语使用逗号、中文逗号或换行分隔，最多 `8` 项，每项最多 `64` 个字符；支持目标短语，不承诺理解关系、动作和排除条件等复杂自然语言指令。Prompt 为空时由后端自动选择图中最显眼的主体。检测/分割失败时回退浏览器处理。
4. AI 模式成功和回退成功都进入同一套前端 Pattern、色板匹配、统计、渲染和下载流程。
5. 用户不能关闭背景移除；后端始终输出已移除背景的结果。
6. 主体提取并移除背景后，如果有效主体外侧存在透明边，后端自动裁掉透明外边，并将主体等比放大、居中到目标画幅。放大不得拉伸或裁切主体；至少一个方向贴满画幅，另一方向因宽高比产生的透明边允许保留。该行为强制启用，不增加前端开关。

## 输出与接口边界

- 继续使用统一的 `AlgorithmInput` / `AlgorithmOutput` 和既有 HTTP 信封，不新增顶层响应字段。
- 响应信封保持 `code`、`msg`、`data`、`exec`、`meta.accept_id`、`meta.perf_time_use`。
- `code != 200` 时 `exec` 可包含异常类型（Exception Class）；前端不得把内部堆栈或图片内容展示给用户。
- `data` 仍为目标宽高的 RGBA 成品格子图，长度严格为 `width * height * 4`。背景 alpha 为透明，主体保留原图 RGB。
- 后端不执行拼豆色板匹配、抖动、拼豆统计、渲染或导出，也不把色板传给后端。
- “复古像素画色彩量化”由前端针对用户选定的拼豆色板完成，后端不增加独立的非拼豆颜色量化。

## 算法能力边界

- 检测器根据 Prompt 产生多个候选主体区域，先按默认置信度阈值 `0.35` 和 NMS 去除重复框，再由分割器逐候选生成精细 Mask。最终合并通过筛选的 Mask 并集，默认最多保留 `5` 个实例；同一主体的重复 Mask 使用默认 Mask IoU 阈值 `0.7` 去重。
- 各实例 Mask 独立修复后再做并集，默认不对不同实例执行跨区域形态学连接，避免填入两个主体之间的背景。若真实样本证明存在明显的同一主体碎裂，再把连接距离作为可配置参数讨论。
- Prompt 为空时不把空文本直接传给依赖文本编码的检测器。优先使用 MobileSAM 自动 Mask 候选，以预测质量、稳定性、合理面积、中心显著性和较弱的边界惩罚进行排序，选择最显眼主体；过滤近似整图背景和过小噪点。若无法得到可靠候选则回退浏览器。
- 边缘增强只作用于保留主体及其邻域，避免把已判定的背景纹理重新引入结果；增强是 RGB 视觉锐化/轻度描边，不等同于把 Canny 图直接绘制成黑边。
- 固定分辨率输出沿用统一输出契约。由于背景最终强制透明，差异化采样发生在主体内部和轮廓保护区之间：主体内部使用正常采样，轮廓保护区使用更细粒度采样，减少普通 Resize 导致的轮廓丢失。
- 透明边裁切以修复后的有效主体 Mask 为准。多主体场景使用全部保留实例 Mask 的联合包围盒，保持实例之间的相对位置；参与计算前应去除已判定的孤立噪点。若联合包围盒未覆盖原画幅，则裁切到包围盒后等比缩放到目标画幅并居中；若已覆盖原画幅则不做构图缩放。空 Mask 仍视为算法失败，不得伪造全画幅主体。
- 构图缩放不得改变主体宽高比，不得为追求横纵两个方向同时铺满而裁掉主体。缩放后至少一个方向与目标画幅边界相接，另一方向可保留对称透明区域；后续边缘增强、轮廓保护和固定分辨率采样基于重构后的主体画幅执行。
- 本需求不承诺复杂场景的主观语义理解；检测和分割失败必须是可识别的算法失败并触发前端回退。

## 模型与运行时约束

- 模型文件不得提交到 Git，不得在请求路径自动下载；通过显式安装/预取流程和配置的本地模型目录管理，并校验版本、哈希和许可证。
- 经公开工件验证，未找到可确认来源的 `ultralytics/yolo-world-nano`。POC 锁定实际可获取的 `yolov8s-worldv2.pt`（25,923,032 字节）+ `mobile_sam.pt`（40,728,226 字节），动态 Prompt 还必须使用 CLIP `ViT-B-32.pt` 文本编码器（353,976,522 字节），完整权重为 420,627,780 字节（约 401 MiB）。精确链接和 SHA-256 记录在 `data/model/download.md`。
- 当前 Ultralytics 运行库和分发的 YOLO-World 工件采用 AGPL-3.0，原 YOLO-World 项目为 GPL-3.0，MobileSAM 为 Apache-2.0，OpenAI CLIP 为 MIT。POC 可继续技术验证，但在超出演示/评估环境前，部署方必须确认 AGPL-3.0 与实际分发模式兼容；不再沿用未经验证的“整套约 35MB”估算。
- POC 生产运行时采用 NVIDIA CUDA GPU + PyTorch。生产默认且仅承诺 `cuda` 设备；CUDA、显存不足或 PyTorch 模型加载失败时视为后端不可用，自动回退浏览器，不得在生产环境静默降级到 CPU。
- 开发环境允许通过显式配置启用 `cpu` 调试设备，以验证模型加载、Prompt 检测、NMS、分割、Mask 合并、透明边裁切、边缘增强、像素化、HTTP 契约和回退链路。CPU 调试使用 FP32，并禁用 CUDA autocast、FP16、CUDA 预热和显存统计；不承诺 CPU 性能，也不将 CPU 结果作为 CUDA 算子兼容性、显存、并发或 `3` 秒性能验收依据。Intel XPU 和 DirectML 仍不在本阶段范围内。
- 单个服务进程常驻一份模型，每张 GPU 默认推理并发为 `1`，其他请求排队；首版不实现动态批处理。模型推理不得阻塞 ASGI 事件循环，必须有受控的线程/执行器、输入尺寸、队列和超时边界。
- 模型在服务启动阶段加载和预热，不把冷启动加载成本放入首个用户请求。热启动单图处理目标不超过 `3` 秒，单请求超时为 `30` 秒；若真实模型基准无法达到，必须在 SPEC 复审后调整，不能静默降低验收目标。
- 不持久化用户原图、Base64 或中间 Mask；日志只记录请求 ID、算法阶段、耗时和错误类型等非敏感信息。

## 验收方向

- 模式选择、Prompt 输入、Generate/等待/Download 状态和控件锁定行为正确。
- 模型未安装、加载失败、Prompt 无效、检测/分割失败、推理超时、HTTP 错误、空响应或非法 RGBA 结果均自动回退并显示通知。
- 后端成功响应符合统一信封、目标尺寸、RGBA 长度和透明背景约束，且前端后续色板与 Pattern 行为不变。
- 在约定的真实样本上，相比 `browser_native` 和 `cv_native` 记录主体保留、背景误保留、边缘质量和耗时指标。
- 对存在透明外边、主体已贴边、多个主体、细长主体和空 Mask 的样本验证构图归一化：不得拉伸或裁切有效主体，多主体相对位置保持不变，输出尺寸和 Alpha 契约不变。
- 在 NVIDIA CUDA 验收设备上，模型预热后的单图处理不超过 `3` 秒；每张 GPU 推理并发为 `1`，单请求超时为 `30` 秒。实际 CUDA/PyTorch 版本、显存峰值和模型缓存大小必须在工件验证后记录。

## 已确认事项

已确认：

- 最终拼豆颜色量化交给前端，后端不做额外颜色量化。
- 允许替换为实际可获取且许可证兼容的轻量模型。
- Prompt 支持多主体，允许为空；空 Prompt 默认选择最显眼主体。
- 多主体采用逐候选分割、Mask 去重和并集合并；默认检测置信度 `0.35`、最多 `5` 个实例、Mask IoU 去重阈值 `0.7`，不同实例默认不做跨区域形态学连接。
- Prompt 使用逗号、中文逗号或换行分隔目标短语，最多 `8` 项、单项最多 `64` 个字符，不承诺复杂自然语言指令理解。
- 空 Prompt 使用 MobileSAM 自动 Mask 候选和显著性排序近似选择最显眼主体。
- POC 生产使用 NVIDIA CUDA GPU + PyTorch，不提供生产 CPU/XPU/DirectML 推理回退；开发环境允许显式启用 FP32 CPU 调试，但不参与性能和部署验收。
- 检测、分割或后端运行失败时回退浏览器处理。
- 背景强制透明，差异化像素采样发生在主体内部和轮廓保护区之间。
- 轻量 AI 模式始终显示；仅在后端能力接口确认算法和模型可用时允许选择，不可用时显示原因；运行期故障触发浏览器回退。
- 模型启动时常驻和预热，每张 GPU 默认推理并发 `1`，首版不做动态批处理；热启动单图目标不超过 `3` 秒，请求超时 `30` 秒。
- 正式算法标识和首版版本为 `tiny_model@1.0.0`。
- 去除背景后自动裁掉透明外边，并将全部有效主体的联合包围盒等比放大、居中到目标画幅；不拉伸、不裁切主体，不提供关闭开关。

## 实施前验证项

以下内容属于实施验证，不再作为产品需求选择题：

1. 锁定实际可获取且许可证兼容的检测/分割模型工件、版本、哈希和下载来源。
2. 在 NVIDIA CUDA 环境验证 PyTorch、Torchvision、检测器、MobileSAM 和 NMS 算子兼容性。
3. 基准测试模型预热时间、热启动单图耗时、显存峰值、模型缓存大小和排队行为。
4. 当前开发机未检测到 NVIDIA CUDA，GPU 验收必须在具备 NVIDIA CUDA 的设备执行；本机可通过显式 CPU 调试配置运行模型功能链路，也可运行不依赖真实模型的前端、契约和回退测试，但不得据此确认 CUDA 兼容性或性能指标。

## 非目标

- 不替换或删除现有 `browser_native`、`cv_native`。
- 不改变前端拼豆色板、Pattern 数据结构、统计、渲染和导出契约。
- 不实现大参数量 VLM、云端推理服务或通用语义理解承诺。
- 不在本阶段锁定未经下载和测试验证的模型工件、性能数字或部署体积。
