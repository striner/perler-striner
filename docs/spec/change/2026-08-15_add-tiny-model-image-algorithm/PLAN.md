# 轻量终端 AI 图像像素化实施计划（草案）

## 计划状态

- 状态：等待 `SPEC.md` 确认
- 前置条件：`SPEC.md` 正式确认；可用的 NVIDIA CUDA 验收环境

## 阶段 1：规格和工件锁定

- 做什么：按已确认的颜色量化归属、Prompt 语义、多目标合并、失败策略和性能门槛，实际验证候选检测/分割工件、许可证、哈希与 NVIDIA CUDA/PyTorch 支持。
- 回应目标：SPEC 的输出边界、模型约束和验收方向。
- 结果：形成可下载、可离线缓存、可在目标环境运行的版本清单；若候选不可用，记录替代方案。

## 阶段 2：运行时与模型存储

- 做什么：增加模型目录配置、显式预取/校验命令、启动加载与预热、加载状态和资源上限；禁止请求时下载，运行时固定为 NVIDIA CUDA + PyTorch。每张 GPU 默认并发 `1`，请求排队且单请求超时 `30` 秒。
- 回应目标：模型文件不入 Git、不持久化原图、CUDA GPU 并发和超时约束。
- 结果：模型缺失、损坏、许可证不匹配和加载异常可转换为统一算法错误。

## 阶段 3：算法包骨架与统一契约

- 做什么：建立 `algorithms/tiny_model/`，包含 descriptor、参数 schema、model store、runtime、detector、segmenter、pipeline 和 service；检测器与分割器使用接口隔离。
- 回应目标：独立算法注册、后续可替换多套模型、复用统一输入输出。
- 结果：即使真实模型尚未接入，也能完成能力描述、参数校验和可控失败；模型推理通过线程/执行器运行。

## 阶段 4：真实流水线接入

- 做什么：非空 Prompt 解析最多 `8` 个目标短语，采用检测候选、NMS、逐实例轻量分割、Mask IoU 去重和并集合并；空 Prompt 使用 MobileSAM 自动 Mask 候选及显著性排序。随后完成主体约束下的边缘锐化/轻度描边、主体内部与轮廓保护区差异化采样和 RGBA 输出，并复用现有前端色板流程。
- 回应目标：主体保留、背景移除、边缘保护、固定分辨率和前端职责边界。
- 结果：输出可直接被现有 Pattern 消费，不包含后端色板量化字段。

## 阶段 5：前端模式和回退

- 做什么：增加始终可见的轻量 AI 模式、能力接口驱动的可用/禁用状态和原因、Prompt 控件、Generate 状态机和运行期失败回退通知；保持旧模式行为和请求过期保护。
- 回应目标：用户可控触发、处理中锁定、失败仍可用。
- 结果：后端成功或回退均只形成一个当前 Pattern 结果。

## 阶段 6：测试和样本验收

- 做什么：覆盖契约、模型生命周期、Prompt/多主体合并、超时/并发、非法输出、前端状态和真实样本对比。
- 回应目标：SPEC 的验收方向与历史回退约束。
- 结果：在 NVIDIA CUDA 设备记录 PyTorch 预热和热启动耗时、显存、模型缓存大小、主体误删、背景误保留、边缘质量，并验证热启动单图 `3` 秒目标和 `30` 秒超时边界。
