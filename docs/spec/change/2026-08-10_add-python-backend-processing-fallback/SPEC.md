# Python 后端图片处理与前端回退

## 文档状态

- 状态：已确认
- 日期：2026-08-10

## 背景

当前工程是完全静态的前端应用。用户上传的原图由浏览器缩放为拼豆网格尺寸的 RGBA 像素数据，随后由前端完成背景移除、拼豆色板匹配、抖动、统计、预览和导出。

现在需要将工程调整为包含前端和 Python 后端两个子项目。用户上传图片后，前端优先请求 Python 后端获得“成品格子图”；后端结果可用时，继续交给既有前端拼豆逻辑处理；后端不可用或结果无效时，自动使用现有浏览器图片处理方式完成同样的格子图准备，保证核心功能仍可使用。

本需求改变了当前“图片永不上传、全部在浏览器本地处理”的隐私承诺。启用后端地址时，用户上传的原图会发送到配置的后端服务；相关项目说明必须同步更新。

## 术语

### 成品格子图

图片处理阶段的最终输出，是已经完成目标尺寸缩放和背景移除的二维 RGBA 网格。网格宽高等于目标拼豆网格宽高，每个格子保存尚未映射到任何拼豆品牌色板的红、绿、蓝、透明度信息；被移除的背景格通过透明度标记为空格。

成品格子图是图片算法的最终结果，但不是拼豆业务的最终 `Pattern`，不包含拼豆品牌、色板索引、颜色用量或拼豆总数。

### 后端成功

后端在允许时间内返回非空、格式合法、尺寸和数据长度均符合请求的成品格子图。

### 后端失败

包括未配置或无法访问后端、请求超时、网络错误、非成功 HTTP 状态、空响应、无法解析的响应，以及尺寸或像素数据不合法等情况。

### HTTP 响应信封

Python 后端能够返回响应时，无论成功或失败，响应体都必须包含以下字段：

- `code`：整数状态码，`200` 表示成功，非 `200` 表示失败；
- `msg`：字符串消息；
- `data`：成功时为当前接口的业务载荷，其中图片处理接口返回成品格子图；失败时为 `null`；
- `exec`：异常类型，成功时为 `null`；`code` 非 `200` 时可返回异常类名字符串，没有对应异常类时也可为 `null`；
- `meta.accept_id`：非空字符串请求标识，用于关联单次请求；
- `meta.perf_time_use`：非负数值，表示后端处理该请求所用的毫秒数。

字段名及嵌套层级固定。图片处理接口中，成品格子图的版本、宽、高和 RGBA 字节数据均放在 `data` 内。`exec` 只允许包含异常类名，不包含模块路径、异常消息或调用堆栈。

### 统一算法输入输出

所有后端算法必须使用同一套输入结构和同一套输出结构，不得为单个算法增加专属顶层字段或返回另一种结果格式。

统一输入表达协议版本、原图内容与媒体类型、目标网格宽高、算法标识、可选算法版本以及算法参数对象。统一输出表达协议版本、实际算法标识与版本、网格宽高和按行排列的 RGBA 字节。

HTTP multipart 只是统一输入的传输编码。Web 层完成一次归一化后，算法层不接收 FastAPI `UploadFile`、表单对象或其他 Web 框架类型。算法差异只能通过统一输入内的 `algorithm_params` 对象表达；无论参数如何变化，成功输出仍必须是统一成品格子图。

## 目标

### G1：形成前后端两个子项目

原有 Astro/React 应用成为独立前端子项目；新增可独立安装、启动和测试的 Python 后端子项目。两者通过有版本的 HTTP 接口通信。

### G2：后端优先处理用户上传图片

用户上传原图后，在配置了后端服务的环境中，前端应优先把原始图片、目标网格尺寸以及算法选择信息发送给后端。后端框架把请求分发给指定的已注册算法；算法必须完成图片缩放和背景移除并输出成品格子图，不负责拼豆品牌或色板判断。

本次只建设后端框架，不注册生产算法。处理接口在没有可用算法时应返回结构化的未实现结果，使前端自动执行本地回退。后续接入算法后无需修改稳定 HTTP 信封和前端格子图消费逻辑。

当用户修改会改变目标网格尺寸的设置时，应按新的处理条件重新获得成品格子图。仅修改拼豆品牌、抖动、网格显示、预览缩放或高亮等后续选项时，不应重复上传原图。

### G3：保留既有拼豆处理行为

无论成品格子图来自后端还是浏览器本地回退，前端只读取其中已经确定的实体格/空格及其 RGBA 颜色，并负责颜色增强、拼豆色板匹配、可选抖动、用量统计、预览和 PNG 导出。前端的 `Pattern` 生成阶段不再执行背景移除。

### G4：后端失败时自动回退

任何后端失败都不得阻断图案生成。前端应自动采用需求实施前的浏览器缩放和背景移除算法生成成品格子图，再继续执行同一套拼豆处理逻辑。

回退不要求用户重试、刷新或手动切换，也不向用户展示技术错误。

### G5：结果安全性与一致性

前端只能使用经过完整校验的后端结果。过期请求的响应不得覆盖较新的图片或目标尺寸对应的结果。后端不得持久化用户上传图片。

### G6：保持静态前端可部署

前端生产物仍为可部署到 GitHub Pages 或普通静态服务器的静态文件。Python 后端独立部署，前端通过构建时公开配置获得其地址；未配置后端地址时应用仍可通过本地处理正常使用。

### G7：预留高并发 GPU 多算法架构

Python 后端应采用适合高并发 GPU 模型调用的服务框架，并形成清晰的 Web、配置、协议、服务、算法抽象、算法注册与基础设施分包。GPU 推理不得直接阻塞 Web 请求事件循环；框架应为后续独立模型 worker、并发控制、批处理、超时、资源分配和横向扩展保留接入位置。

后端应支持按稳定接口参数选择算法及可选版本，并通过受约束的算法参数对象传递算法专属选项。增加新的算法实现时，应以新增独立算法包和注册配置为主，不要求修改通用路由、响应信封或前端 `Pattern` 逻辑。

所有算法包、注册表、模型服务网关和测试替身都必须消费相同的算法输入类型并返回相同的算法输出类型。通用服务层应在结果进入 HTTP 信封前再次校验输出契约，拒绝尺寸、RGBA 长度或类型不合法的算法结果。

## 用户可感知行为

1. 用户上传受支持的图片，页面仍按当前交互生成、预览和导出拼豆图案。
2. 后端存在匹配的已注册算法且正常返回时，页面使用该算法完成缩放和背景移除后的成品格子图。
3. 本次交付因不包含生产算法，后端处理接口返回未实现状态，页面自动显示由原有浏览器流程生成的图案。
4. 后端异常、超时或返回空/非法数据时，页面同样自动显示由原有浏览器流程生成的图案。
5. 用户快速更换图片或网格宽度时，最终页面只展示最新选择对应的结果。
6. 页面不再提供是否移除背景的开关，后端算法和浏览器本地回退都必须生成已移除背景的格子图。
7. 示例图片不属于用户上传原图，可继续使用浏览器本地流程并强制执行背景移除。

## 范围边界

### 本次包含

- 将现有前端整理为独立子项目。
- 新增 Python 后端子项目和图片处理 HTTP 接口。
- 建设适配高并发 GPU 模型服务的基础框架、工程分包、算法协议、注册表、分发层和配置入口。
- 在接口参数中预留算法标识、算法版本和算法专属参数对象。
- 提供算法能力查询和“未注册/未实现”标准响应。
- 定义并校验成品 RGBA 格子图的数据契约。
- 规定未来后端算法必须执行目标尺寸缩放和背景移除，接口不提供关闭背景移除的参数。
- 将现有前端背景移除能力保留在本地回退处理器中，而不是 `Pattern` 生成阶段。
- 移除前端背景移除开关，使后端优先与本地回退保持相同强制语义。
- 前端后端优先、失败回退和请求竞态处理。
- 前后端各自的开发、构建、测试和配置说明。
- 调整现有 GitHub Pages 构建路径及关于图片上传/隐私的说明。

### 本次不包含

- 将拼豆品牌、色板匹配、抖动、统计、渲染或导出迁移到后端。
- 任何可随生产服务运行的图片处理或示例算法，包括基础缩放、背景移除、AI 模型和语义分割；只允许在自动化测试内部注入不进入生产装配的假实现。
- GPU 模型文件、GPU 推理运行时、真实动态批处理效果和 GPU 压力/性能验收。
- 用户账号、鉴权、数据库、对象存储或上传图片留存。
- 指定云平台的后端生产部署流水线、域名、TLS 或运维资源。
- 修改现有拼豆色板和最终 `Pattern` 数据结构。
- 为回退过程增加新的页面提示、状态组件或人工切换按钮。

## 约束

- 前端与后端之间只传递图片处理所需信息，包括原图、目标尺寸和算法选择，不传递背景移除开关、拼豆品牌或色板数据。
- 算法选择信息包含稳定的算法标识、可选版本和受大小/结构限制的参数对象；算法参数不得改变统一响应信封和成品格子图结构。
- 前端只有同时配置后端地址和算法标识时才发起后端处理请求；算法版本可省略，算法参数默认使用空对象。
- Web、服务、算法注册和模型服务层之间只使用统一算法输入输出结构；禁止把 FastAPI/BentoML 专属请求对象作为算法契约，禁止算法返回专属顶层字段。
- 所有算法成功结果必须经过统一输出校验后才能写入响应 `data`；输出协议版本、算法标识/版本、网格尺寸、RGBA 类型或长度不合法时按算法契约错误返回，并由前端回退。
- 后端结果必须能无损还原为浏览器 `ImageData` 等价数据：宽、高以及按行排列的 RGBA 字节。
- 网格尺寸必须与前端请求的目标尺寸一致，像素数据长度必须等于 `width * height * 4`。
- 每个 RGBA 分量取值范围为 0 至 255；后端或本地回退处理器负责用 alpha 标记背景空格，后续前端逻辑继续以 alpha 小于 128 表示空格。
- 背景移除是成品格子图的强制不变量，不属于算法可选参数，也不得通过 `algorithm_params` 提供关闭入口。
- 后端故障不能改变本地回退结果的算法与含义；本地回退继续使用当前浏览器缩放和背景移除算法。
- 后端服务必须允许通过配置限制跨域来源，并对上传大小、图片格式和网格尺寸进行限制。
- 后端自行产生的成功、校验失败和内部错误响应必须使用统一 HTTP 响应信封；后端无法控制的网络中断或上游代理空响应除外。
- 前端只有在 HTTP 状态成功、`code` 为 `200`、`data` 非空且信封与格子图均通过校验时才能采用后端结果；`exec` 不作为成功判断标志，但其类型仍需符合协议。
- 本次生产代码不得包含图片缩放、背景移除、模型推理或伪造成功格子图的算法实现；无匹配算法时必须返回非 `200` 的未实现信封。
- 测试可以注入仅存在于测试代码中的假算法，以验证成功响应契约、注册分发和前端成功路径。

## 验收标准

### AC1：项目结构

- 仓库中存在可独立安装和运行的前端、Python 后端子项目。
- 根目录文档能够说明两者职责和本地联调方式。
- GitHub Pages 工作流能够从新的前端目录完成静态构建。

### AC2：后端成功路径

- 上传有效图片时，前端向已配置的后端发送原图和目标网格尺寸，不发送背景移除选择。
- 请求同时携带算法标识、可选算法版本和算法参数对象。
- 注入测试假算法并返回合法成品格子图后，前端将其交给收窄后的 `generatePattern` 逻辑进行色板匹配和统计。
- 成功响应同时包含 `code`、`msg`、`data`、`exec`、`meta.accept_id` 和 `meta.perf_time_use`，字段类型与约定一致。
- 可通过受控测试数据证明最终图案使用了后端结果，而不是本地缩放结果。

### AC3：失败回退路径

- 未配置后端、网络错误、超时、非成功状态、空响应和非法响应均自动走原有本地处理。
- 后端在线但算法未注册或未实现时同样自动走原有本地处理。
- 缺少响应信封字段、字段类型错误、`code` 非 `200` 或 `data` 为空均视为后端失败。
- 上述失败均不会导致图案区域永久为空或阻止用户继续调整、预览和导出。

### AC4：处理边界

- 图片处理接口的成功响应 `data` 只表达已经完成缩放和背景移除的 RGBA 格子图及算法标识，不包含色板索引或最终 `Pattern`。
- 前端不存在背景移除开关；切换拼豆品牌时不重新请求后端，而是基于当前成品格子图重新生成 `Pattern`。
- 背景移除由后端优先路径或浏览器本地回退路径强制完成；色板匹配、抖动、统计、渲染和导出仍在前端执行。

### AC5：竞态与校验

- 快速连续上传图片或修改目标网格宽度时，过期响应不会覆盖最新结果。
- 尺寸不一致、RGBA 长度错误或字段非法的响应会被拒绝并触发本地回退。
- 后端返回的 `accept_id` 可唯一关联一次请求，`perf_time_use` 为非负毫秒数。

### AC6：隐私与数据生命周期

- 文档明确说明配置后端后原图会上传，并说明未配置或失败时的本地回退行为。
- 后端处理完成或失败后不持久化上传文件。

### AC7：验证

- 前端静态构建通过。
- 后端自动化测试覆盖健康检查、空算法能力列表、统一响应信封、未实现错误、算法标识/版本/参数分发、测试假算法成功路径、非法输入和空/错误输入。
- 前端自动化测试覆盖响应信封与后端结果解析、失败回退、请求中不存在背景移除参数、强制本地背景移除和过期请求保护。
- 本地联调可验证后端在线和离线两条完整路径。

### AC8：后端框架与多算法扩展

- 后端 Web、协议模型、统一异常、业务服务、算法接口、算法注册/分发和模型服务基础设施位于职责清晰的独立包中。
- 生产算法注册表为空；处理请求返回符合信封协议的未实现错误，不生成成品格子图。
- 测试假算法能够通过注册表按算法标识和版本被分发，算法专属参数能够以受约束对象传入。
- 至少两个不同标识或版本的测试假算法使用相同输入输出类型完成分发验证，且不能通过增加专属顶层字段改变契约。
- 测试假算法返回不符合统一输出结构的结果时，服务拒绝该结果并返回统一错误信封。
- 算法能力接口能够返回当前已注册算法及版本；本次生产环境返回空列表。
- 技术文档说明未来 GPU 算法如何声明资源、配置并发/批处理、注册服务和接入统一接口。
- 不宣称已经验证真实 GPU 吞吐量；该项必须在实际模型接入后单独进行压力测试。

## 待确认事项

初版按以下口径编写：

1. 后端返回已经完成目标尺寸缩放和背景移除、但尚未匹配拼豆色板的 RGBA 成品格子图；接口不接收 `remove_background`，算法参数也不能关闭背景移除。
2. 后端服务地址未配置时，直接采用本地流程。
3. 后端处理失败对用户静默回退，不新增状态提示或人工开关。
4. 本次 Python 后端只提供 Web 与 GPU 模型服务基础框架、分包、统一协议、算法抽象和注册分发，不实现或注册任何生产图片算法。
5. 本次只提供后端的本地运行与部署基础，不选择具体云平台。
6. HTTP 响应采用固定信封：`code: number`、`msg: string`、`data: object | null`、`exec: string | null`、`meta.accept_id: string`、`meta.perf_time_use: number`；成功 `code` 为 `200` 且 `exec` 为 `null`，失败时 `exec` 可为 Exception Class 的类名字符串；耗时单位为毫秒。
7. 后端请求通过 `algorithm`、可选 `algorithm_version` 和 `algorithm_params` 预留多算法选择；本次因无生产算法，处理接口正常返回未实现错误并触发前端本地回退。
8. “输入输出结构一致”指所有算法之间分别共享统一输入类型和统一输出类型；原图输入与格子图输出因职责不同不要求字段完全相同。
