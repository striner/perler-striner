## 背景

当前工作区在桌面端采用左右两栏：左侧依次堆叠图像输入、图纸设置和超参数，右侧显示图纸结果与色表。输入图像预览和选择图片控件位于同一卡片中，导致原图观察区域偏小；生成按钮又处在图纸设置末尾，输入、确认对象、配置和生成的操作层级不够清晰。

本需求只调整前端工作区的信息架构和响应式布局，不改变 Browser Native、CV Native、Tiny Model 的算法、接口、状态机或失败回退行为。

## 目标

将工作区调整为上下两行、每行左右两栏：

1. 第一行左侧为“输入图像参数”面板，包含选择图片、试用实例、处理模式和对象选择；右侧为独立的输入图像预览，支持拖入图片；桌面端左右面板严格等高。
2. 第二行左侧顶部为 Generate/Download 主操作按钮，其下为两个同级的一级可折叠面板：“图纸设置”和“超参数”；右侧为图纸结果。
3. 保留现有各模式的条件显示、控件锁定、分析等待、生成等待、下载和浏览器回退行为。
4. 在窄屏设备上按任务顺序纵向排列，所有文本和控件不得溢出或重叠。

窄屏下不保留双栏，按照“输入控制 → 输入预览 → 生成与参数 → 图纸结果”的顺序排列。断点沿用工程现有大屏断点，避免引入仅服务单个页面的特殊设备判断。

## 用户可感知行为

1. “选择图片”和“试用实例”始终位于第一行左侧输入图像参数面板；按钮行为保持不变。
2. 处理模式位于选择图片按钮组下方。切换模式的分析取消、结果失效和 Tiny Model 自动分析行为保持不变。
3. 输入图像预览从参数面板中分离到第一行右侧。无图时显示拖入提示；有图时完整展示原图，不进行填充裁切。
4. 用户可把图片拖入预览区域完成首次上传或替换当前图片。生成或分析期间沿用现有锁定规则，不接受拖入、点击选图或试用实例操作。
5. Tiny Model 分析期间，等待遮罩显示在输入预览上；分析成功后 bbox 继续叠加在预览上，对象复选列表显示在左侧输入图像参数面板。点击 bbox 或复选框仍同步选择同一实例。
6. 非 Tiny Model 模式不显示对象选择区域；桌面端输入参数面板仍与预览面板等高，内容保持顶部对齐。
7. 第一行和第二行之间使用横跨完整工作区的明确分隔线及留白，不能只依赖卡片间距区分板块。
8. Generate/Download 是第二行左侧的独立主操作，不属于任一折叠面板。按钮继续呈现分析中、生成中、待生成和可下载状态。
9. “图纸设置”和“超参数”是同一级可折叠面板。图纸设置默认展开，超参数默认折叠；折叠只影响显示，不修改参数、不触发分析或生成。
10. 超参数仅在当前模式提供可配置项时显示；Browser Native 下不显示空的超参数面板。
11. 图纸结果、规格摘要、画布、空状态和结果色表均位于第二行右侧。色表只在生成结果存在时显示。
12. 后端回退通知继续悬浮显示 5 秒并允许手动关闭，不因布局调整改变位置逻辑或可访问性语义。

## 内容归属

| 区域 | 包含内容 |
| --- | --- |
| 第一行左侧：输入图像参数 | 选择图片、试用实例、处理模式、模式不可用原因、Tiny Model 对象选择列表与选择校验 |
| 第一行右侧：输入图像预览 | 原图、空状态、拖入区域、Tiny Model 分析遮罩与 bbox |
| 第二行左侧：生成与配置 | Generate/Download 按钮、图纸设置折叠面板、超参数折叠面板 |
| 第二行右侧：图纸结果 | 结果空状态、规格摘要、Pattern 画布、色表 |

“处理模式”属于输入图像参数。切换到 Tiny Model 后，如果已有输入图片，沿用现有行为立即分析；对象列表随当前模式和分析结果在同一输入参数面板中出现或消失。

## 响应式与视觉约束

- 大屏采用两列，小于现有 `lg` 断点时变为单列。
- 桌面端第一行左右卡片使用同一 Grid 行高并拉伸等高；第二行保持由各自内容决定高度。
- 两行之间使用横跨全部列的 2px 中性分隔线，并保留足够上下间距。
- 输入预览和图纸结果均使用稳定的最小高度，加载遮罩、空状态、bbox 标签或画布出现时不得推动相邻列宽度变化。
- 原图采用 `object-contain`，完整显示，不为填满预览区域裁切内容。
- 拖入激活态必须有明确边框和背景反馈；锁定态必须同步禁用键盘、点击和拖入操作。
- 折叠面板标题行应具有展开/收起图标、`aria-expanded` 和关联内容区域，不依赖颜色表达状态。
- 继续使用现有 Card、Button、Select、Slider、Switch 等组件和中性色视觉体系，不引入新的页面级设计语言。
- 不在卡片内部再嵌套装饰性卡片。折叠面板使用分隔线或轻量边框表达层级。

## 验收标准

- 桌面端呈现两行双栏，第一行是输入参数/输入预览，第二行是生成配置/图纸结果，上下两行列边界对齐。
- 桌面端第一行左右面板外边界高度一致，处理模式紧跟选择图片按钮组，两个板块之间具有清晰的全宽分隔线。
- 移动端按草图顺序单列显示，不出现横向页面滚动、按钮文字溢出、bbox 标签遮挡关键控件或面板重叠。
- 预览区域支持拖入首次选择和替换图片；按钮选图与试用实例仍可用。
- Tiny Model 对象分析、bbox 点击、复选框选择、至少选择一个实体的校验均正常。
- 图纸设置和超参数可以独立展开、折叠；折叠不改变当前值和生成状态。
- Browser Native、CV Native、Tiny Model 的 Generate/等待/Download、控件锁定和失败回退行为无回归。
- 图纸画布、摘要和色表全部显示在第二行右侧，原有缩放、网格、高亮和下载行为正常。
- 前端 Vitest、Astro check 和生产构建通过，并使用 Chrome 在桌面与移动视口完成截图和交互验收。

## 已确认事项

- 工作区采用两行布局，每行均为左侧控制、右侧视觉结果。
- 第一行左侧包含选择图片、试用实例和对象选择；右侧输入预览支持拖入。
- 第二行左侧包含独立生成按钮，以及“图纸设置”“超参数”两个一级折叠面板；右侧为图纸结果。

## 已确认的布局约定

1. 图纸设置默认展开，超参数默认折叠。
2. 结果色表继续放在第二行右侧图纸结果下方。
3. 移动端按“输入参数 → 输入预览 → 生成与配置 → 图纸结果”的顺序纵向排列。

## 非目标

- 不改变图像处理算法、后端 API、Pattern 数据结构或拼豆色板逻辑。
- 不改变 Tiny Model 上传后自动分析和对象选择流程。
- 不新增图片编辑、裁切、缩放、平移或 bbox 调整能力。
- 不重新设计站点页头、语言切换、页脚或品牌视觉。
