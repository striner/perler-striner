# 图像输入与图纸生成工作区布局调整实施计划

## 计划状态

- 状态：已完成
- 前置条件：`SPEC.md` 及布局草图、折叠默认状态、色表归属和移动端顺序已由用户确认

## 阶段 1：布局语义重组

- 做什么：将当前左右两栏重组为上下两行、共享列轨道的工作区结构。
- 回应目标：形成第一行输入参数/输入预览和第二行生成配置/图纸结果。
- 怎么实现：在 `PerlerStudio.tsx` 中按语义拆分四个主要区域，使用一个响应式 Grid 管理两列；第一行左右卡片按同一行高拉伸，并在两行之间增加横跨全部列的分隔线；保持现有状态、回调和数据流，不复制处理逻辑。
- 结果：桌面两行的左栏宽度一致、右栏自适应，移动端按既定工作流单列排列。

## 阶段 2：输入控制与独立预览

- 做什么：把选择图片、试用实例、对象选择和输入图像预览拆分到第一行左右两侧。
- 回应目标：放大原图观察面积，并使拖入目标清晰独立。
- 怎么实现：保留隐藏文件输入和 `loadFile`；将拖放、键盘选择、分析遮罩与 bbox 叠加迁移到预览区域；将处理模式放到选图按钮组下方，将对象列表保留在输入参数区，并复用既有选择同步与锁定判断。
- 结果：按钮上传、试用实例、预览拖入、Tiny Model 自动分析和对象选择均无行为变化。

## 阶段 3：生成主操作与一级折叠面板

- 做什么：把 Generate/Download 按钮移到第二行左侧顶部，将图纸设置与超参数改为同级折叠面板。
- 回应目标：明确“生成”是配置区的主操作，同时降低长参数列表对结果浏览的干扰。
- 怎么实现：新增独立的图纸设置展开状态，复用现有超参数展开状态；标题按钮使用 Chevron 图标、`aria-expanded` 和稳定内容 ID。条件模式控件、重置默认值和失效生成逻辑保持不变。
- 结果：两个面板可独立折叠，Generate/Download 状态不受折叠影响，Browser Native 不产生空超参数面板。

## 阶段 4：图纸结果归并与响应式细节

- 做什么：把结果摘要、画布、空状态和色表统一放入第二行右侧，并完善不同视口的尺寸约束。
- 回应目标：结果信息形成单一视觉区域，避免布局移动和控件重叠。
- 怎么实现：结果区域保持画布滚动容器；色表作为结果后的同级内容，不嵌套 Card；为预览、结果、按钮和 bbox 标签设置响应式宽高与溢出约束。
- 结果：桌面与移动端均能完整查看原图和图纸，动态内容不改变列轨道或造成页面横向滚动。

## 阶段 5：验证

- 做什么：验证布局、交互、可访问性和三个处理模式的行为回归。
- 回应目标：满足 SPEC 的桌面/移动草图和既有生成契约。
- 怎么实现：更新必要的组件测试；运行前端 Vitest、Astro check 和生产构建；启动 Astro 后使用 Chrome 检查桌面与移动视口，覆盖拖入、选图、试用实例、面板折叠、Tiny Model bbox/复选框、Generate/Download 和回退通知。
- 结果：自动化检查通过，关键视口截图符合草图，控制台无新增错误。
