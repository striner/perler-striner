# CV Native 后端算法与前端处理模式

## 文档状态

- 状态：已完成
- 日期：2026-08-12
- 依赖需求：[Python 后端图片处理与前端回退](../2026-08-10_add-python-backend-processing-fallback/SPEC.md)

## 背景

现有工程已经具备前后端分离、统一图片算法输入输出、后端优先与浏览器回退能力，
但生产算法注册表为空。用户上传图片时，后端返回未实现结果，前端静默使用浏览器
本地算法，页面也无法主动选择处理方式或感知发生了回退。

本需求增加第一个可用于生产装配的后端图片算法 `cv_native`。该算法不加载机器学习
模型，仅使用传统计算机视觉方法生成已经缩放并移除背景的 RGBA 成品格子图。前端
同时增加处理模式选择，并在后端模式失败、实际使用浏览器回退时给出短暂提示。

## 与历史需求的关系

本需求依赖上一需求形成的双子项目、统一 `AlgorithmInput` / `AlgorithmOutput`、HTTP
信封和本地回退能力，并有意替代其中两项阶段性约束：

- “生产算法注册表为空”改为默认注册 `cv_native`；
- “后端失败静默回退”改为继续自动回退，同时显示 5 秒可关闭通知。

其余边界继续有效：后端输出仍是未匹配拼豆色板的 RGBA 格子图；拼豆品牌匹配、
抖动、统计、渲染和导出仍属于前端；背景移除仍不可关闭。

## 术语

### 处理模式

用户在“Pattern settings / 图纸设置”中选择的格子图生成方式。本次提供：

- `cv_native`：上传原图到 Python 后端并请求 OpenCV 原生算法；失败时自动回退。
- `browser_native`：不请求后端，直接使用现有浏览器本地缩放与背景移除算法。

处理模式不是拼豆品牌，也不改变统一成品格子图和最终 `Pattern` 的数据结构。

### CV Native

不依赖训练权重、推理模型或外部模型服务的传统计算机视觉算法。它负责输入解码、
前景/背景分割、背景移除、前景边缘增强、区域感知的像素化和目标尺寸 RGBA 输出。

GrabCut 在本需求中只表示基于颜色分布和空间先验的前景/背景图割，不宣称能够识别
“人物、宠物、商品”等语义类别，也不等价于模型语义分割。

### 回退通知

用户选择 `cv_native` 后，因后端未配置、网络错误、超时、非成功响应、空响应、非法
响应或算法执行错误而改用 `browser_native` 时出现的非阻断通知。通知只说明已改用
浏览器处理，不展示异常类、响应原文、堆栈或图片内容。

## 目标

### G1：增加明确的处理模式选择

在 Pattern settings 的第一个设置项增加模式下拉框。用户可选择 `CV Native` 或
`Browser Native`；模式变化会基于当前原图和目标尺寸重新获取成品格子图，但不会
改变拼豆品牌、抖动、网格显示、缩放或高亮设置。

配置了有效后端地址时默认选择 `cv_native`；未配置后端地址时默认选择
`browser_native`。内置示例没有原始上传文件，始终在浏览器处理，不显示回退通知。

### G2：后端失败时显示可关闭的回退通知

选择 `cv_native` 且实际发生自动回退时，页面显示本地化通知。通知自动停留 5 秒，
也可以通过关闭图标立即关闭。新的回退事件发生时复用同一个通知并重新开始 5 秒
计时，避免堆叠多个重复通知。

通知不得阻断本地处理、预览、设置调整和导出；后端故障仍然不能导致图案区域永久
为空。主动选择 `browser_native` 不属于失败，不显示通知。

### G3：提供零模型的 CV Native 成品格子图算法

后端注册稳定算法标识 `cv_native` 和首个版本 `1.0.0`。算法应在不加载任何模型的
前提下完成以下能力：

- 解码受支持的输入图片并保留有效透明度；
- 降低会干扰前景/背景判断的图像噪声；
- 结合透明度、空间和颜色分布提取主要前景并移除背景；
- 修复前景掩码中的小孔洞、毛刺和孤立噪点；
- 仅在保留前景内部及其轮廓附近检测和增强边缘，忽略已移除背景中的纹理边缘；
- 在前景掩码约束下生成目标网格，减少背景颜色渗入主体边缘；
- 输出宽高严格等于请求目标尺寸、长度严格等于 `width * height * 4` 的 RGBA 字节。

后端流水线必须在目标网格缩放前完成主体判断。处理顺序固定为：原图解码与资源校验、
工作分辨率预处理、前景/背景 Trimap 构造、GrabCut 前景提取、Mask 修复、前景限定的
边缘检测与增强、Mask 感知的目标网格采样、RGBA 输出。JPG 输入没有 alpha 时不得把
边缘位置直接视为背景；主体接触一条或多条图像边界时仍应有机会被保留。

边缘增强是输出图像上的视觉增强，不只是给采样器提供保护信息。它不是全图描边，也
不是将 Canny 结果直接绘制成黑色像素。它包含两部分：

- 在修复后的前景 Mask 及其膨胀邻域内提取 Canny/梯度边缘，生成边缘保护带；已判定为
  背景的纹理边缘不得进入该保护带。
- 对前景及边缘保护带执行受控的局部锐化，使轮廓和内部结构边缘更清晰；允许叠加低
  强度、颜色自适应的轻度描边，但不得产生明显黑边、白边或大面积光晕。
- 目标网格采样时提高边缘附近前景像素的权重，禁止背景像素参与边界格主体颜色平均；
  采样保护是增强的辅助机制，不能替代实际 RGB 锐度增强。

后端算法分包应保持协议层、生产装配层和 `cv_native` 流水线解耦，以便后续增加其他
算法时只新增算法包和注册项，不修改统一 HTTP 信封或前端 `Pattern` 结构。

### G4：保持算法选择与统一契约一致

前端选择 `cv_native` 时使用现有 `/api/v1/process`、响应信封和格子图校验，不增加
算法专属顶层字段。`GET /api/v1/algorithms` 应返回 `cv_native@1.0.0` 的能力说明，
包括无需 GPU、当前不支持动态批处理、始终移除背景和受支持参数 schema。

### G5：控制 CPU 算法的资源与失败边界

OpenCV 计算不得直接阻塞 FastAPI 事件循环。算法应限制解码后的像素规模、工作图
尺寸、并发数和 OpenCV 内部线程，避免压缩图片解码膨胀或并发线程过量占用内存与
CPU。无法可靠形成合法前景或输出时返回统一算法错误，由前端完成带通知的回退。

上传图片仍不得由应用代码持久化，日志不得记录图片字节、Base64 内容或算法内部
大数组。

### G6：保持现有拼豆业务与静态部署能力

无论选择哪种模式，最终格子图继续进入同一个前端色板匹配、抖动、统计、预览和
导出流程。前端仍可构建为静态站点；没有 Python 服务时 `browser_native` 保持完整
可用。

### G7：提供可控的手动生成与 CV 超参数

选择 `cv_native` 时，在 Pattern settings 下方显示独立的 Hyperparameters 面板，允许
调整前景恢复、粗尺度主体保护、边缘种子以及输出锐化相关参数。所有值通过既有
`algorithm_params` JSON 传递，后端必须按能力 schema 校验类型与范围；不增加新的 HTTP
顶层字段，也不允许关闭背景移除。

上传新图片、切换处理模式、修改目标宽度或 CV 超参数后，现有成品结果失效，主按钮显示
Generate；这些动作不得立即触发图片处理。用户点击 Generate 后才开始处理，处理期间按钮
显示等待状态并禁用上传、模式、宽度和超参数等会改变本次输入的控件。后端成功或完成浏览器
回退并生成最终 Pattern 后，主按钮恢复为 Download。品牌、抖动、网格和预览缩放仍只作用于
当前已生成格子，不重新调用后端。

## 用户可感知行为

1. 模式下拉框位于 Pattern settings 的第一项，拼豆品牌选择顺延到第二项。
2. 配置后端时，首次上传默认使用 `CV Native`；上传后主按钮显示 Generate，点击后才请求后端。
3. 选择 `Browser Native` 后，点击 Generate 在浏览器处理，不产生后端请求。
4. `CV Native` 请求失败时，页面继续生成本地图案，并显示“后端处理失败，已改用浏览器处理”含义的通知。
5. 通知在 5 秒后消失，也可点击关闭图标立即消失；连续失败不会堆叠多条通知。
6. 切换处理模式、修改目标宽度或 CV 超参数只标记待生成，不立即处理；切换品牌、抖动、
   网格、预览缩放或高亮不会重复上传。
7. 页面继续不提供背景移除开关，两个模式都输出已移除背景的格子图。
8. Hyperparameters 只在 CV Native 模式显示；生成期间显示等待并锁定生成相关控件，完成后
   主按钮变为 Download。

## 范围边界

### 本次包含

- 前端处理模式类型、模式下拉框、默认选择和本地化文案。
- `cv_native` 成功、失败和本地直通三种格子图获取结果的明确区分。
- 5 秒自动关闭、可手动关闭、不会堆叠的回退通知。
- Python 生产包中的 `cv_native@1.0.0` 算法及生产注册。
- OpenCV/NumPy 运行依赖、算法参数约束、CPU 并发和输入资源限制。
- 传统 CV 的降噪、GrabCut 前景提取、掩码修复、前景边缘增强、区域感知像素化和固定尺寸输出。
- 算法能力查询、API 成功路径、前端消费与端到端回退验证。
- 更新前后端 README、环境示例、PRD、技术方案和隐私/能力说明。
- CV Native Hyperparameters 面板、后端参数 schema 和手动 Generate 状态机。

### 本次不包含

- 任何下载、加载或调用机器学习模型、神经网络权重或外部分割 API。
- 将 GrabCut 描述为可识别业务语义类别的真正语义分割。
- 用户手绘前景/背景种子、矩形框选、掩码编辑或交互式抠图。
- 对输出颜色执行 K-Means 或其他颜色量化，以及把拼豆品牌色板传给后端。分割阶段允许
  聚类边框颜色样本以估计多峰背景分布，但不得用聚类中心改写输出 RGB。
- 新增第二个后端算法、GPU 加速、动态批处理或真实高并发性能承诺。
- 改变最终 `Pattern`、拼豆色板、渲染、统计或导出结构。

## 约束

- `cv_native` 必须复用唯一的 `AlgorithmInput` / `AlgorithmOutput`，不得接收 FastAPI
  或 BentoML 对象，不得扩展成功响应顶层字段。
- `browser_native` 只存在于前端，不作为后端算法标识发送。
- 背景移除是两个模式的强制不变量，不增加 `remove_background` 或等价关闭参数。
- 后端不得对输出执行颜色量化或聚类；区域采样得到的 RGB 颜色直接进入统一 RGBA 输出，
  由前端基于用户选择的真实拼豆色板完成唯一一次业务量化。
- 显式边缘检测必须在初始背景分割和掩码修复之后执行，只处理保留前景内部及其轮廓
  邻域；已判定为背景的纹理边缘不得进入后续增强。增强必须实际提高输出 RGB 的局部
  锐度，允许有限轻描边，但不得只生成内部保护 Mask 后宣称已完成边缘增强。
- 输入自带 alpha 时优先使用透明度作为强先验；无 alpha 时允许使用保守的空间先验
  初始化 GrabCut。无法构造有效前景/背景样本时应返回算法错误，而不是伪造成功。
- 算法输出必须确定目标宽高、RGBA 字节类型和长度，背景格 alpha 必须小于 128。
- 模式切换和宽度变化必须取消或忽略旧请求；旧请求的成功、失败或通知都不能覆盖
  最新选择。
- 上传、模式、宽度或 CV 超参数变化不得自动请求；只有当前 Generate 操作可以提交请求。
- 生成期间必须锁定生成输入；生成完成并形成当前 Pattern 后才允许 Download。
- 回退通知不显示技术错误；技术诊断只进入不含图片内容的后端日志或开发者控制台。
- 当前 API 信封字段 `code`、`msg`、`data`、`exec`、`meta.accept_id`、
  `meta.perf_time_use` 保持不变。

## 验收标准

### AC1：模式选择

- 模式下拉框是 Pattern settings 的第一个设置项，包含 `CV Native` 和
  `Browser Native`，中英文页面文案完整。
- 有后端配置时默认 `cv_native`，无后端配置时默认 `browser_native`。
- 选择本地模式不产生图片处理 HTTP 请求；切换模式只进入待生成状态，点击 Generate 后才处理当前上传图片。

### AC2：回退通知

- `cv_native` 的网络错误、超时、非 2xx、错误信封、空响应和非法格子图都会继续
  生成本地图案并显示通知。
- 通知约 5 秒自动关闭，支持点击关闭图标，具有可访问名称和通知语义。
- 连续失败只显示一个通知并重置倒计时；主动本地模式和内置示例不显示通知。
- 旧请求失败不能在用户已经切换模式、图片或宽度后显示过期通知。

### AC3：生产算法注册与能力

- `GET /api/v1/algorithms` 返回且只返回当前生产算法 `cv_native@1.0.0`。
- 能力描述声明 `requires_gpu: false`、`supports_batching: false`、
  `removes_background: true` 和受约束参数 schema。
- 使用合法图片调用 `POST /api/v1/process` 返回 `200` 统一信封，算法身份、目标
  尺寸和 RGBA 长度正确。

### AC4：CV 处理结果

- 透明 PNG 的透明背景保持为空格，主体 alpha 保持实体。
- 对具有明显主体与边界背景的合成测试图，输出背景透明、主体保留且边界没有明显
  大面积背景色渗入。
- 输出保留区域采样得到的 RGB，不包含聚类中心、颜色数量限制或拼豆色板字段。
- 同一输入与参数的结果满足测试所需的稳定性，不因并发请求发生交叉污染。
- 对含有清晰主体轮廓、细长结构和主体贴边的测试图，输出的前景轮廓和内部结构边缘
  应比未增强采样更清晰，边缘保护带能够减少轮廓断裂、背景色混入和主体格子误删；
  不得通过向背景绘制边缘来获得该结果。

### AC8：相对浏览器基线的改进

- 使用同一组 JPG/PNG fixture 分别运行 `browser_native` 和 `cv_native`，记录主体误删格、
  边界背景污染格和边缘断裂格。
- `cv_native` 在主体贴边 fixture 上不得比浏览器基线删除更多主体格；在至少一个细节或
  边界 fixture 上应减少背景污染或边缘断裂。
- 对无法建立可信前景/背景样本的图片，`cv_native` 返回受控算法错误并触发前端回退，
  不得以“成功”状态返回明显失真的透明格子图。

### AC5：错误和资源限制

- 空图片、无法解码图片、过大解码尺寸、非法参数、无法形成有效掩码和内部 CV 错误
  使用统一错误信封，不返回部分成功格子图。
- CPU 计算在线程执行边界内运行；并发限制和 OpenCV 线程设置可配置并有测试覆盖。
- 生产代码和依赖中不存在模型文件、模型下载、模型推理框架或外部分割 API。

### AC6：保持前端业务边界

- `cv_native` 输出继续由前端完成品牌色板匹配、抖动、统计、渲染和导出。
- 品牌、抖动、网格、缩放和高亮变化不重复请求后端；宽度和模式变化会重新请求。
- 两种模式均无背景移除开关，最终 `Pattern` 数据结构不变。

### AC7：验证

- 后端算法单元测试、注册/能力/API 集成测试、参数与资源限制测试通过。
- 前端客户端、模式选择、通知计时/关闭、回退、竞态和不必要重传测试通过。
- Ruff、后端 Pytest、前端测试、Astro 类型检查和生产构建通过。
- 本地联调验证 `cv_native` 成功、后端停止后的通知回退和 `browser_native` 不发请求。

### AC9：超参数与手动生成

- CV Native 模式显示 Hyperparameters 面板，Browser Native 模式隐藏该面板。
- 面板参数与后端 descriptor/校验范围一致，修改后只进入待生成状态，不立即发送请求。
- 上传、切换模式和修改宽度同样只进入待生成状态；点击 Generate 才处理最新快照。
- 处理期间显示等待状态并禁用生成输入，处理成功或回退完成并形成 Pattern 后显示 Download。
- 品牌、抖动、网格和缩放继续即时作用于当前结果，不把按钮改为 Generate，也不请求后端。

## 待确认事项

初版采用以下推荐口径，请确认或指出需要修改之处：

1. 模式固定为 `CV Native` 与 `Browser Native` 两项；配置后端时默认前者，未配置时默认后者。
2. 回退提示使用一条不暴露技术细节的通知，停留 5 秒；连续失败复用并重置计时。
3. GrabCut 按“零模型前景提取”验收，不承诺真正语义识别；复杂场景失败时允许回退浏览器算法。
4. 先完成背景分割和 Mask 修复，再对保留前景及其轮廓邻域执行 Canny、视觉锐化和可选
   轻度描边；边缘增强必须反映在输出 RGB 中。
5. 后端不对输出做 K-Means 或其他颜色量化；分割阶段可用聚类描述背景色域，但最终且
   唯一的业务颜色量化由前端针对真实拼豆色板执行。
6. `cv_native` 首版标识/版本为 `cv_native@1.0.0`，生产环境默认注册且声明无需 GPU。
