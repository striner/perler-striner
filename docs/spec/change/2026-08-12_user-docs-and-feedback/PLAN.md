# 用户说明文档与反馈入口接入技术计划

> 本计划基于 `SPEC.md` 当前版本形成。若 `SPEC.md` 后续调整，本文件需要同步更新。

## 1. 页面入口规划

### 1.1 右上角说明文档入口

- 做什么：在主页面顶部导航区域增加“说明文档”入口。
- 回应目标：对应 `SPEC.md` 的“用户说明文档入口”和“说明文档入口验收”。
- 怎么实现：
  - 修改 `src/components/HomePage.astro` 的 header 区域。
  - 在语言切换按钮旁增加说明文档链接。
  - 链接地址从国际化文案配置读取，避免中英文页面硬编码。
  - 中文页面配置为 `/perler-striner/pages/guide/zh/`。
  - 英文页面配置为 `/perler-striner/pages/guide/en/`。
- 期望结果：用户在页面右上角可以看到并点击说明文档入口，并跳转到对应语言的系统内置说明文档。

### 1.2 右下角悬浮反馈入口

- 做什么：在主页面右下角增加固定悬浮反馈入口。
- 回应目标：对应 `SPEC.md` 的“用户反馈入口”和“后续客服扩展预留”。
- 怎么实现：
  - 在 `src/components/HomePage.astro` 中添加右下角固定圆角悬浮反馈入口。
  - 反馈入口首版仅作为轻量跳转/联系方式入口，不实现系统内反馈表单和数据存储。
  - 样式使用 Tailwind CSS，保持与当前页面风格一致。
  - 通过位置、尺寸和层级控制，避免遮挡主要操作区域。
- 期望结果：用户在桌面端和移动端都能看到右下角反馈按钮，点击后可以进入简单反馈渠道。

## 2. 系统内置说明文档规划

### 2.1 新增中英文说明文档页面

- 做什么：在系统内新增中英文双版本说明文档页面。
- 回应目标：对应 `SPEC.md` 的“用户说明文档内容”和“说明文档阅读体验”。
- 怎么实现：
  - 新增 `src/pages/pages/guide/zh/index.astro`，对应 `/perler-striner/pages/guide/zh/`。
  - 新增 `src/pages/pages/guide/en/index.astro`，对应 `/perler-striner/pages/guide/en/`。
  - 页面引入现有全局样式，保持视觉风格与主系统一致。
  - 页面提供返回主系统入口和中英文切换入口。
- 期望结果：说明文档随系统一起构建和发布，不依赖外部文档平台。

### 2.2 文档内容结构

- 做什么：在系统内置说明文档中提供必须覆盖的内容结构。
- 回应目标：对应 `SPEC.md` 的新手上手指南、参数解释、常见问题和版本更新记录要求。
- 怎么实现：
  - 中文和英文说明文档均应包含以下章节：
    1. 系统是什么
    2. 使用前你需要知道
    3. 从零开始的新手上手指南
    4. 每个设置项是什么意思
    5. 如何判断生成结果是否合适
    6. 常见问题
    7. 版本更新记录
  - 版本更新记录采用人工维护或 AI 总结。
  - 版本更新记录字段包括：时间、操作人、版本、更新内容、用户可感知变化。
  - 将“每次版本更新/合并 master 前必须更新说明文档版本记录”写入说明文档版本记录章节和本需求交付说明。
- 期望结果：普通用户无需理解技术细节，也能跟随站内文档完成完整流程；版本更新记录有明确维护规则。

## 4. 反馈渠道规划

### 4.1 轻量反馈入口

- 做什么：让用户可以通过右下角入口进入一个轻量反馈渠道。
- 回应目标：对应 `SPEC.md` 的“为反馈入口提供一个可用的反馈渠道”和“后续客服扩展预留”。
- 怎么实现：
  - 首版不实现系统内反馈填写、数据存储、后台管理或自动邮件发送。
  - 点击反馈按钮后跳转到外部问卷链接 `https://v.wjx.cn/vm/wFChGhh.aspx`。
  - 问卷平台负责问题填写、提交确认、数据存储和后续查看。
  - 推荐问卷字段保持简洁：反馈类型、反馈标题、反馈内容、联系方式（选填）。
- 期望结果：在没有后端和数据库的当前阶段，用户仍能找到反馈渠道；后续接入后端后再升级为系统内反馈表单。

### 4.2 问卷反馈可行性

- 做什么：评估并预留问卷作为反馈渠道的实现方式。
- 回应目标：对应 `SPEC.md` 的“反馈数据存储后置”和“当前阶段轻量反馈渠道”。
- 怎么实现：
  - 从技术上，问卷反馈适合当前静态站点：只需要一个外部链接。
  - 从数据上，问卷平台可以解决当前没有数据库的问题。
  - 从用户体验上，跳转问卷比打开邮件客户端更稳定，也更容易收集结构化信息。
  - 本次已确认问卷链接为 `https://v.wjx.cn/vm/wFChGhh.aspx`。
- 期望结果：本次反馈入口直接跳转问卷，邮箱仅作为说明文档中的补充联系方式。

## 5. 验证规划

### 5.1 静态检查与构建

- 做什么：验证代码和 Astro 页面可以正常构建。
- 回应目标：对应 `SPEC.md` 的验收标准。
- 怎么实现：
  - 运行 `npm run build`。
  - 如需要进一步检查，运行 `npx astro check` 或项目已有检查命令。
- 期望结果：构建成功，无页面路由或类型错误。

### 5.2 人工验收

- 做什么：确认用户可感知行为符合预期。
- 回应目标：对应 `SPEC.md` 的说明文档入口、说明文档内容、反馈入口验收。
- 怎么实现：
  - 使用 `astro dev --background` 启动本地服务。
  - 访问中文和英文页面。
  - 检查右上角说明文档入口是否可见、可点击。
  - 检查说明文档入口是否分别指向 `/perler-striner/pages/guide/zh/` 和 `/perler-striner/pages/guide/en/`。
  - 检查中英文说明文档页面内容和版本更新记录区域。
  - 检查右下角反馈入口是否可见、可点击。
  - 检查反馈入口是否跳转到 `https://v.wjx.cn/vm/wFChGhh.aspx`。
  - 调整浏览器宽度，检查移动端布局下入口是否仍可用。
- 期望结果：入口、文档和反馈渠道均可用，不影响原有上传、生成、下载流程。
